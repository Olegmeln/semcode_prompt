# Codec Specification v0.2

## 1. Назначение

Codec уменьшает размер передачи между системами при сохранении однозначного Semantic IR.

## 2. Заголовок

Каждый payload начинается с версии словаря:

```text
@D:FM-0.2
```

Расширенный заголовок:

```text
@D:FM-0.2;h:sha256:<hash>;ir:0.2
```

## 3. Правила кодирования

1. Кодировать только значения, определённые словарём.
2. Не менять порядок там, где он семантически значим.
3. Использовать JSON-escape для свободного текста.
4. Не кодировать неизвестное значение ближайшим похожим токеном.
5. После декодирования валидировать Semantic IR.
6. Сравнивать canonical hash исходного и декодированного IR.

## 4. Неизвестные токены

- обязательный неизвестный токен: `E_UNKNOWN_REQUIRED_TOKEN`;
- необязательный неизвестный токен: сохраняется как extension при разрешении словаря;
- неизвестная версия словаря: `E_DICTIONARY_VERSION`;
- несовпадение hash: `E_IR_HASH_MISMATCH`.

## 5. Режимы словаря

- `inline`: словарь включён в системное сообщение;
- `registry`: модель/агент получает словарь из реестра;
- `cached`: словарь уже подтверждён в сессии;
- `fallback-full`: при ошибке отправляется полный промпт.

## 6. Пример

IR:

```json
{
  "intent": {"action": "create", "object": "financial_model"},
  "target": {"model": "Claude", "environment": "Excel"},
  "requirements": {"scenario_count": 3},
  "constraints": [{"type": "do_not_invent_data"}],
  "output": {"kind": "compiled_prompt"}
}
```

Codec:

```text
@D:FM-0.2;ir:0.2 FM:new t:Cl@X scn:3 !inv →P
```
