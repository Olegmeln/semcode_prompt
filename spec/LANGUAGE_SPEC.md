# SemCode Language Specification v0.1

## 1. Назначение

SemCode — гибридный семантический язык для краткой записи намерения пользователя и последующей компиляции в качественный промпт.

Язык ориентирован не на точное выполнение машинной инструкции, а на совместную работу человека и ИИ. Поэтому одна команда может включать:

- формальные токены;
- сокращения;
- естественный язык;
- персональные псевдонимы;
- ссылки на память;
- недоопределённые элементы.

## 2. Базовая модель команды

```text
<DOMAIN><INTENT><DIRECTION> <EXECUTOR>@<ENV> <OPERATION><OBJECT> <SOURCE> <CONSTRAINTS> <MEMORY> <OUTPUT>
```

Все части необязательны. ИИ восстанавливает пропуски из текущего контекста и памяти.

## 3. Основные токены

### Домены

| Токен | Значение |
|---|---|
| `FM` | финансовое моделирование |
| `DOC` | документы и тексты |
| `HR` | подбор и управление персоналом |
| `LAW` | юридические документы |
| `DATA` | данные и аналитика |
| `PRES` | презентации |
| `DEV` | программирование и разработка |
| `GEN` | общий режим |

Домены расширяемы и могут быть персональными.

### Намерения

| Токен | Значение |
|---|---|
| `task` | описываемая задача |
| `P?` | нужен готовый промпт |
| `code?` | нужна кодированная версия запроса |
| `plan?` | нужен план выполнения |
| `audit?` | нужна проверка |
| `fix?` | нужно исправление |
| `build?` | нужно создание артефакта |

### Операции

| Токен | Значение |
|---|---|
| `new*` | создать новый объект |
| `edit~` | изменить существующий объект |
| `short-` | сократить |
| `expand+` | расширить |
| `merge&` | объединить |
| `split/` | разделить |
| `check!` | проверить |
| `compare<>` | сравнить |
| `map#` | построить карту/индекс |

Знак интенсивности может повторяться:

```text
new*      обычное создание
new**     создание с более глубокой проработкой
expand++  значительное расширение
short--   сильное сокращение
```

### Исполнитель и среда

```text
Cl@Excel      Claude, встроенный в Excel
GPT@Chat      ChatGPT в диалоге
GPT@API       OpenAI API
Agent@Word    агент в Word
Local@PC      локальная модель или локальный сервис
```

### Источник

| Токен | Значение |
|---|---|
| `in docs` | использовать документ |
| `in docs+` | использовать несколько приложенных документов |
| `in @last` | использовать последний результат |
| `in mem` | использовать память |
| `in repo` | использовать репозиторий |
| `in sheet:T1` | использовать указанную таблицу |

### Память

| Токен | Значение |
|---|---|
| `mem+` | использовать релевантную память |
| `mem++` | использовать память и обновить её после выполнения |
| `mem-` | не использовать долговременную память |
| `remember:key` | сохранить конкретное правило |
| `forget:key` | удалить конкретное правило |

### Результат

| Токен | Значение |
|---|---|
| `→P` | вернуть готовый промпт |
| `→code` | вернуть только кодированную команду |
| `→both` | вернуть код и готовый промпт |
| `→json` | вернуть машинное представление |
| `→artifact` | создать артефакт |
| `→diff` | показать разницу |

## 4. Нечёткая семантика

SemCode допускает недетерминированные команды. Модель должна:

1. распознать вероятное намерение;
2. использовать контекст диалога и память;
3. заполнить несущественные пропуски разумными допущениями;
4. оценить уверенность;
5. уточнять только то, что существенно меняет результат.

### Уровни уверенности

```text
conf:H   высокая уверенность
conf:M   средняя уверенность
conf:L   низкая уверенность
```

Правило:

- `H` — выполнять без уточнений;
- `M` — выполнять, явно указав допущения;
- `L` — задать один наиболее важный уточняющий вопрос.

## 5. Нормализация команды

Пользователь может написать:

```text
ФМtask-ответ нужен промт для ? Cl eexc new* in докс+
```

Автокодировщик должен нормализовать это в:

```text
FMtask→P? Cl@Excel new*FM in docs+ mem? →both
```

Затем сформировать интерпретацию и готовый промпт.

## 6. Допустимые гибридные команды

```text
FMtask→P? Cl@Excel new*FM in docs+ учти три сценария
```

```text
LAW edit~ §4.1 =sense =law сделай короче →clean
```

```text
PRES build? GPT@Chat new*deck in docs+ стиль=инвестор →artifact
```

Естественный язык после формальных токенов интерпретируется как дополнительные ограничения.

## 7. Правило памяти

Память делится на:

- `profile` — устойчивые предпочтения пользователя;
- `project` — знания о текущем проекте;
- `task` — контекст текущей задачи;
- `session` — временные выводы текущего диалога;
- `macro` — пользовательские сокращения и макрокоманды.

При конфликте приоритет:

```text
явная текущая команда > текущий документ > task > project > profile
```

## 8. Формат ответа автокодировщика

По умолчанию:

```text
CODE:
<нормализованная команда>

INTENT:
<краткая расшифровка>

PROMPT:
<готовый качественный промпт>

ASSUMPTIONS:
<только значимые допущения>

CONFIDENCE:
H | M | L
```

Если пользователь пишет `→P`, вернуть только готовый промпт.

## 9. Принцип развития

Новые токены не проектируются заранее без необходимости. Они добавляются после повторения одной и той же пользовательской конструкции минимум в нескольких реальных задачах.
